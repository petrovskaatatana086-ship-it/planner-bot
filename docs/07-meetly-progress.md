# Meetly — журнал выполнения

## Правила ведения

Каждый этап заканчивается отдельным отчётом в чате и записью здесь: что сделано, что проверено, результат, ограничения и точка продолжения. Логи команд проверок хранятся в `docs/meetly-logs/`, решения — в документации, изменения — отдельными коммитами в `dev`. Не коммитить чужие незавершённые изменения. Не сохранять секреты, initData и реальные персональные данные. Журналы приложения сохраняются отдельно от проверок; сырые HTTP-заголовки, тела и параметры авторизации не логируются.

## 21.10.2026 — этап 4: обработчик очереди и адаптеры уведомлений

- Реализован OutboxWorker: короткая транзакция получения задания, lease 90 секунд, timeout сети 30 секунд, выполнение адаптера вне write-lock, отдельная фиксация результата. run(stop) завершает ожидание по событию остановки; при отмене сетевой операции задание остаётся с lease для восстановления.
- Миграция 0007 добавляет lease_token. Просроченный worker не может подтвердить/изменить задание, захваченное новым worker. Это защита состояния БД, а не гарантия exactly-once во внешнем сервисе.
- Временные ошибки повторяются через 5с/30с/2м/10м/30м; учитывается Retry-After, затем failed. Есть внутренний повтор failed-задания с тем же ID; будущий API обязан проверять владельца, version и idempotency. Неизвестный адаптер не считается успешной отправкой.
- Порядок сохраняется по типу сущности, ID и каналу; будущие Google-операции блокируются предыдущей failed-операцией той же встречи. Постоянный отказ уведомления владельцу не блокирует последующее подтверждение клиенту. Переносы и Google sync ещё не подключены.
- Добавлены BookingDeliveries для request.created/request.approved: Telegram как plain text; SMTP с постоянным Message-ID и явным skipped при отключённой почте. Устаревшие уведомления помечаются superseded, настроенный Google не обходится, тексты внешних ошибок/адреса не сохраняются в error_code.

## 21.10.2026 — этап 4: долговечная синхронизация Google Calendar

- Добавлены CalendarSync и миграция 0008: environment/calendar binding, стабильные event ID и conference request ID, desired/applied version, последние применённые интервалы и безопасный код ошибки. enqueue_calendar_sync вызывается только внутри транзакции общей команды; повтор той же версии не сбрасывает synced в pending.
- Добавлен GoogleEventGateway с ограничением тела ответа/тайм-аутом, кодами ошибок без сырых ответов, одним обновлением токена после 401, Retry-After, раздельной обработкой квот/прав, ETag для PATCH/DELETE и восстановлением отсутствующей отмены 404/410.
- GoogleTokens получает/обновляет существующие зашифрованные credentials: сеть выполняется без write-lock, запись проверяет, что подключение не сменилось. Отключённая/изменённая авторизация не восстанавливается старым сетевым ответом.
- CalendarDeliveries обрабатывает meeting.sync: GET перед INSERT, тот же ID после timeout/409, сверка перед повтором PATCH, удаление при отмене, пропуск создания уже отменённой встречи, коалесцирование старого задания к актуальному desired state. Служебные private properties отделяют окружение/встречу; чужие события и немаркированные legacy не перезаписываются.
