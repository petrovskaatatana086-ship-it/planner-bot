# Кнопки переноса и отмены в Telegram-боте

Пользователь выявил проблему на live meetly-test: «Мои встречи» выводил только
текст, а перенос/отмена были доступны исключительно текстовыми командами.
Предыдущая инструкция проверять перенос через карточку была неточной.

Теперь каждая встреча выводится отдельной карточкой с русским статусом.
Будущие confirmed/rescheduled встречи получают кнопку «Перенести», активные
встречи также — «Отменить встречу». При reschedule_pending второй перенос
не предлагается, отмена доступна. Исторические/отменённые встречи без действий.
При выключенном runtime кнопки изменения не показываются.

Перенос запрашивает дату/время ДД.ММ.ГГГГ ЧЧ:ММ по Москве; проверка доступности,
сроков, доступа, версии и запись выполняются общими командами. Это текстовый
ввод, календарный выбор в этой форме ещё не добавлен. Прежнее время сохраняется
до согласования, выход из формы не меняет встречу. FSM остаётся MemoryStorage:
после рестарта незавершённую форму нужно открыть заново.

Отмена требует отдельного подтверждения с ID/версией карточки. Callback identity
даёт стабильный ключ; повтор доставки не увеличивает версию второй раз.
Чужие, старые и недоступные записи не открывают форму изменения.

Администратор видит pending переносы отдельно от новых заявок в «Новые заявки»:
исходное/предложенное время и кнопки согласования/отказа. Отказ запрашивает причину.
Карточка фиксирует Meeting.version и конкретный RescheduleRequest.id. BotBooking
сохраняет явно переданный ID предложения вместо замены его текущим pending ID.
Владельцу в outbox-уведомлении дана ссылка-инструкция открыть «Новые заявки».

карточка → форма → запрос → owner inbox → согласование; подтверждение отмены/replay;
