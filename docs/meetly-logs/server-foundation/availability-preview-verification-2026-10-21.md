# Общий подбор времени: границы проверки

Работа выполнена в dev на временных SQLite; Google/Telegram заменены fake
transport. Рабочие .env, БД и сервер не использовались. Миграций схемы в этом
изменении нет, текущий head остаётся 0011. Runtime выключен по умолчанию.

Полный регресс: **260 тестов OK**, 169.749с, exit code 0. Лог
`full-availability-preview-tests-2026-10-21.txt`, subprocess с Python UTF-8 mode,
сохранён объединённый вывод и проверен returncode. В наборе 22 новых проверки
availability и существующие команды, outbox, миграции и оба транспорта бота.

- Одинаковые чистые правила расписания и локальных конфликтов применяются
  к превью и командной проверке перед записью/переносом.
- Учтены частичные пересечения, один buffer и точная его граница, дневной лимит,
  активные/истёкшие/пустые резервы, notice/horizon, выходные/объединённые окна.
- Дни ограничены 31 календарным днём, UI поддерживает следующий/предыдущий период.
  Полностью занятая первая страница не закрывает доступ к следующему месяцу.
- Read BEGIN закрывается до Google. Независимый engine может записать резерв
  во время fake network call; результат повторного чтения исключает занятый слот.
- Смена реальных настроек без increment version, изменение расписания,
  блокировка во время сети и snapshot старше 5с не дают устаревший список.
- Перенос использует длительность своей встречи, исключает только её event ID
  и не предлагает тот же start. Чужая встреча и pending клиентского переноса
  отклоняются до обращения к Google.
- Реальные функции start/choose_date/choose_time проверены с fake Message/FSM:
  stale settings, новая резервация, листание и безопасная ошибка Google.
- Превью не создаёт BookingRequest/OutboxEvent и не резервирует интервал.
  Финальная команда обязательно проверяет доступность заново.

Результат является снимком доступности, а не гарантией до отправки формы.
После показа время может занять другой клиент или внешний участник календаря.
Остаются binding/access writers, legacy adoption и проверка отдельного серверного
окружения; HTTP API/auth ещё не реализованы. Production/master не обновлялись.
