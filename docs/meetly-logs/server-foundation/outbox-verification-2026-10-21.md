# Очередь внешних действий — 21.10.2026

Результат: services/outbox.py, services/booking_deliveries.py, migration 0007 и тесты. Worker не запущен из app.main. Код не развёрнут в production.

Проверки:
- Полный набор 108 тестов OK, full-outbox-tests-2026-10-21.txt.
- После добавления трёх дополнительных тестов адаптеров — 21 тест очереди OK, outbox-tests-2026-10-21.txt. Повтор всего набора не требовался: исполняемый код после полного прогона не изменялся, кроме комментария.
- Migration test выполняет настоящие Alembic Operations 0001–0007 и сверяет метаданные новой схемы с моделями.
- Два SQLite engine: одно задание не захватывается одновременно; истёкший token не может подтвердить новое владение; recovery на точной границе lease.
- Проверены тайм-аут, отмена, retry delays, Retry-After, исчерпание попыток, ручной повтор, FIFO и изоляция каналов/типов сущностей.
- Telegram/SMTP работают через фальшивые транспорты; постоянный SMTP отказ не повторяется, временный повторяется с тем же Message-ID. Отключённая почта — skipped, не sent.
- Устаревшие события — superseded; configured Google — CALENDAR_NOT_SYNCED, без ложного подтверждения календаря.
- Тест специально моделирует падение после remote acceptance до ack: повтор возможен с тем же message ID. SMTP/Telegram не предоставляют общей exactly-once гарантии; стабильный Message-ID не обязывает получателя дедуплицировать письма.

Ограничения:
- Нет Google adapter/calendar_sync, зависимость уведомлений от Google пока fail closed; fallback-уведомление о задержке ссылки будет добавлено с этим адаптером.
- Нет подключения новых команд/worker к handlers, HTTP и жизненному циклу приложения. Старые уведомления не продублированы новым worker, поскольку он не запущен.
- Lease fencing защищает записи БД. SMTP thread после отмены coroutine может продолжить сетевую операцию; поэтому абсолютное отсутствие повторов/одновременных внешних отправок при истёкшей lease не обещается.
- Failed Google останавливает последующие операции того же aggregate до вмешательства, но failed Telegram/SMTP пропускает дальнейшие версии, чтобы ошибка уведомления владельца не блокировала клиента.
- retry_failed — внутренний метод; до открытия через HTTP нужны проверки доступа/версии/ключа.
