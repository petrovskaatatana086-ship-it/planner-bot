# Подключение бота к runtime: границы проверки

Проверки выполнялись локально с временными SQLite-файлами и fake Google/Telegram.
Рабочая БД, .env и сервер не использовались, реальные сообщения не отправлялись.

Итоговый регресс: **237 тестов OK**, 148.371с, exit code 0. Полный лог:
`full-bot-runtime-tests-2026-10-21.txt`. subprocess сохранял объединённый вывод
unittest и его returncode; журнал приведён к UTF-8 без концевых пробелов.
Прежние aiohttp NotAppKeyWarning не являются ошибками тестов.

После узкого исправления преобразования calendar enqueue DeliveryError в безопасный
BookingError: финальный профильный набор **18 тестов OK**, 21.912с. Лог
`bot-booking-final-tests-2026-10-21.txt`. Проверено, что ошибка environment/binding
не сохраняет отмену встречи и не добавляет outbox. Консольный вывод wrapper имел
ошибку кодировки CP1251 после сохранения результата; сам unittest завершился OK,
журнал результата проверен и нормализован в UTF-8.

- Переведены все booking mutation handlers: создание/согласование/отказ заявки,
  запрос/решение переноса, прямой перенос владельцем, отмена владельцем/клиентом.
- Общий BotBooking сохраняет input hash и версии в bot_command_inputs (0011).
  При повторе после commit/ошибки не выбирает новую версию или новое предложение.
- Удалены прежние прямые Google, SMTP и Telegram эффекты из mutation handlers.
  Ответ инициатору остаётся синхронным, уведомления другим участникам — через outbox.
- Проверены реальные функции обработчиков с fake Message/FSM, варианты replay,
  concurrent same key, устаревшая форма/карточка, блокировка и подмена DB role.
- app.main подключает runtime только по BOOKING_RUNTIME_ENABLED=true, требует
  CALENDAR_ENVIRONMENT, проверяет поля схемы, наблюдает за задачей worker.
- Проверены оба транспорта и порядок закрытия HTTP → runtime → Bot. Polling
  обрабатывает обновления последовательно, без detached handler tasks.

Конфигурация по умолчанию выключает mutation handlers без старого fallback. Для
запуска нового пути нужен отдельный мигрированный стенд. На production не включать:
остаются preview availability, Google binding/access writers, принятие legacy
Google events и проверка backup/restore. Миграция на сервере не выполнялась.

Технический флаг не является выключателем будущего Mini App API. При переходе на
новую версию нельзя параллельно запускать старый процесс с прямыми отправками.
