# Технологии проекта

## Python 3.12

Основной язык проекта. Подходит для Telegram-ботов, backend-логики, интеграций и фоновых задач.

## aiogram 3

Фреймворк для Telegram-бота.

Используется для:

- команд `/start` и `/admin`;
- обработки сообщений;
- кнопок меню;
- состояний диалога;
- сценариев регистрации и записи.

## SQLAlchemy 2

Библиотека для работы с базой данных через Python-модели.

Используется для:

- описания таблиц;
- создания записей;
- поиска пользователей;
- хранения заявок;
- хранения встреч;
- аудита действий.

## Alembic

Инструмент миграций базы данных.

Используется для:

- создания таблиц на новой базе;
- контролируемого изменения схемы;
- подготовки PostgreSQL к серверному запуску;
- хранения истории изменений БД в `migrations/versions`.

Команда применения миграций:

```powershell
python -m alembic upgrade head
```

## SQLite

Локальная база по умолчанию для разработки.

Плюсы:

- не нужно ставить отдельный сервер БД;
- удобно для первого запуска;
- подходит для проверки логики.

Минусы:

- не лучший вариант для production;
- позже нужно перейти на PostgreSQL.

## PostgreSQL

Основная база данных для сервера.

Нужна для:

- надежного хранения данных;
- нормальной работы под нагрузкой;
- будущих миграций;
- production-развертывания.

## Redis

Планируется для следующих этапов.

Нужен для:

- очередей задач;
- напоминаний;
- повторных попыток уведомлений;
- временных блокировок и резервов.

## Docker

Нужен для одинакового запуска проекта на локальной машине и сервере.

В проекте уже есть:

- `Dockerfile`;
- `docker-compose.yml`.

## Google OAuth

Нужен для подключения Google-аккаунта владельца.

Без OAuth бот не сможет создавать события в календаре владельца.

Сейчас реализовано:

- переменные окружения `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GOOGLE_REDIRECT_URI`;
- генерация ссылки авторизации Google;
- таблица `oauth_credentials`;
- статус подключения `pending`;
- callback `/google/oauth/callback`;
- обмен `code` на токены;
- сохранение зашифрованных токенов.
- обновление `access_token` через `refresh_token`;
- получение списка календарей;
- выбор основного календаря.
- проверка занятости выбранного календаря;
- создание Google Calendar Event;
- создание Google Meet через Calendar Event.
- обновление Google Calendar Event при переносе;
- отмена Google Calendar Event.
- клиентский запрос переноса с согласованием;
- клиентская отмена в разрешенный срок.

Следующий шаг:

- email-уведомления клиенту.
- напоминания.

## cryptography

Библиотека для шифрования секретов.

Используется для:

- генерации `OAUTH_ENCRYPTION_KEY`;
- шифрования Google `access_token`;
- шифрования Google `refresh_token`.

Команда генерации ключа:

```powershell
python -c "from app.security import generate_encryption_key; print(generate_encryption_key())"
```

## Google Calendar API

Будет нужен для:

- проверки занятости;
- создания событий;
- обновления событий при переносе;
- отмены событий.

## Google Meet

Meet-ссылка создается через событие Google Calendar.

Отдельный Zoom или другой сервис в первом релизе не нужен.

## SMTP

Нужен для email-уведомлений клиенту.

Через SMTP будут отправляться:

- подтверждения;
- отказы;
- переносы;
- отмены;
- приглашения.

## S3-совместимое хранилище

Нужно для резервных копий.

Важно: единственная копия не должна храниться на основном сервере.

## unittest

Стандартный модуль Python для тестов.

Сейчас используется вместо `pytest`, чтобы базовые проверки работали без дополнительных инструментов.

Команда:

```powershell
python -m unittest discover -s tests
```
