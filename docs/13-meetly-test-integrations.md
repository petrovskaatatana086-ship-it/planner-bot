# Meetly test: подключение Google Calendar и почты

## Состояние на 26.10.2026

Основные сценарии Mini App приняты пользователем. Read-only проверка тестового
контейнера показала отсутствие Google OAuth, ключа шифрования и SMTP-настроек.
Compose дополнительно перекрывает эти значения пустыми строками: одного изменения
app.env недостаточно. Production-настройки автоматически не копируются.

В тестовой базе три confirmed-встречи, две отменённые; Google event IDs отсутствуют.
GoogleBindingCommands запрещает изменение calendar_id при любой неотменённой
встрече. Поэтому первому выбору календаря должен предшествовать согласованный
разбор трёх тестовых встреч. Удаление БД, прямое изменение статусов и обход
проверки binding не являются частью подготовки.

## Порядок подключения

1. Выбрать источник OAuth/SMTP и отдельный тестовый календарь. Определить
   контролируемый адрес получателя для новых тестовых заявок.
2. Подготовить OAuth redirect URI
   `https://calendar.tatyana-petrovskaya.ru/meetly-test/google/oauth/callback`.
   Внешний callback должен вести в `/google/oauth/callback` только порта 8013.
   Текущий production callback остаётся на 8012.
3. Подготовить private-конфигурацию теста: GOOGLE_CLIENT_ID,
   GOOGLE_CLIENT_SECRET, GOOGLE_REDIRECT_URI, отдельный OAUTH_ENCRYPTION_KEY,
   SMTP_HOST/PORT/USERNAME/PASSWORD/FROM_EMAIL и режим TLS/SSL.
   Секреты в отчёты и репозиторий не записывать.
4. До включения: snapshot тестовой БД, backup compose/app.env/nginx;
   сохранить состояние production-контейнера и количества тестовых записей.
5. Разобрать активные тестовые встречи через обычные команды по согласованию.
   Подключение календаря само по себе не создаёт события для старых встреч.
6. Убрать только нужные пустые overrides тестового compose, добавить callback,
   проверить compose и nginx, перезапустить только meetly-test и проверить health.
7. Владелец проходит Google OAuth в тестовом боте и выбирает тестовый календарь.
   Пароль Google или коды авторизации в чат не передаются.
8. Создать новую тестовую заявку с контролируемым email, согласовать:
   проверить одно событие, время, ссылки Calendar/Meet и письмо.
   Перенос должен обновить то же событие, отмена — отменить его.
   Отдельно проверить письмо при отклонении заявки и внешнюю занятость слота.
9. Сверить ID/версии, sync/outbox и отсутствие влияния на production.
   Не переотправлять старую очередь уведомлений массово.

## Граница подготовки

Google/SMTP ещё не включены; OAuth и реальные письма не проверены. Требуется
выбор пользователя по источникам подключения. SMTP без учётных данных или
отдельного тестового приёмника в текущей реализации считается отключённым.
