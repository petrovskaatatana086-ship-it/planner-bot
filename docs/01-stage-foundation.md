# Этап 1. Фундамент проекта

## Цель

Создать минимальную рабочую основу Telegram-бота, которую можно запустить локально и проверить без Google-интеграций.

## Что реализуется

- структура Python-проекта;
- конфигурация через `.env`;
- запуск Telegram-бота;
- подключение к базе данных;
- автоматическое создание таблиц при старте;
- определение владельца через `OWNER_TELEGRAM_ID`;
- регистрация клиента;
- базовое клиентское меню;
- базовое меню специалиста-администратора;
- команда `/admin` с серверной проверкой роли;
- базовое логирование;
- первые unit-тесты.

## Основные файлы

- `app/main.py` - точка запуска бота;
- `app/config.py` - настройки окружения;
- `app/bot/handlers.py` - Telegram-сценарии;
- `app/bot/keyboards.py` - кнопки меню;
- `app/bot/states.py` - состояния диалогов;
- `app/db/models.py` - модели базы данных;
- `app/db/session.py` - подключение к БД;
- `app/db/repositories.py` - операции с БД;
- `app/domain/email.py` - проверка email;
- `app/domain/roles.py` - определение роли;
- `tests/` - тесты.

## Сущности БД

- `User`;
- `AuditLog`.

## Как проверить вручную

1. Создать `.env` на основе `.env.example`.
2. Указать `BOT_TOKEN` и `OWNER_TELEGRAM_ID`.
3. Запустить:

```powershell
python -m app.main
```

4. В Telegram открыть бота и отправить `/start`.
5. Проверить регистрацию клиента.
6. Проверить, что владелец видит административное меню.
7. Проверить, что клиенту команда `/admin` отвечает отказом.

## Техническая проверка

```powershell
python -m unittest discover -s tests
python -m compileall app tests
```

## Признаки успешного завершения

- бот запускается;
- `/start` работает;
- клиент может пройти регистрацию;
- владелец определяется через `OWNER_TELEGRAM_ID`;
- таблицы создаются;
- тесты проходят.

## Что не входит

- выбор даты и времени;
- заявки;
- подтверждение заявок;
- Google Calendar;
- Google Meet;
- email-уведомления;
- production-деплой.
