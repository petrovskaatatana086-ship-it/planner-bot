# Mini App: сервер, авторизация и первый тестовый запуск

Рабочий интерфейс: `miniapp/live.html`, `live.js`, `live.css`. Макет `index.html`
остаётся отдельной демонстрацией и не обслуживается рабочим HTTP-маршрутом.
Разрешённые ресурсы `/miniapp/` перечислены явно, каталог/исходники/`.env` не раздаются.
Включение опционально: `MINIAPP_ENABLED=true`, `BOOKING_RUNTIME_ENABLED=true`,
`CALENDAR_ENVIRONMENT=meetly-test`, `MINIAPP_ORIGIN=https://calendar.tatyana-petrovskaya.ru`.
По умолчанию маршруты выключены. Отдельная тестовая SQLite, бот и loopback 8013
сохраняются; production использует 8012 и свой токен/данные.

Публичный адрес теста: `https://calendar.tatyana-petrovskaya.ru/meetly-test/miniapp/`.
Прокси пропускает только `/miniapp/` и `/api/meetly/v1/` тестового процесса.
Шаблон `deploy/meetly-test/miniapp.nginx.conf` добавляется только в HTTPS-блок
существующего домена с предварительным backup, `nginx -t` и проверкой старых маршрутов.
Для API отключён access log, не допускаются повторы POST на другой upstream.

## Авторизация

Используется официальный SDK Telegram; raw initData передаётся только в Authorization
при POST session. HMAC с токеном именно тестового бота, constant-time comparison,
строгие query-поля без дубликатов, возраст до 300с, будущее до 30с, максимум 16КиБ.
Поле signature участвует в check-string, JSON user не сериализуется заново.
Источник алгоритма: https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app.

Сессия — случайные 256 бит на 60 минут, без продления. В SQLite новая additive
миграция 0012 хранит только SHA256, user_id, expires_at/revoked_at. Истёкшие сессии
чистятся при следующем входе. Токен остаётся в памяти вкладки, без localStorage,
cookie или URL. После истечения/перезапуска формы приложение открывают заново.
Роль задаётся только настроенным Telegram ID владельца. Блокировка перепроверяется
на запросах и внутри команд, включая replay. В чужой браузерной вкладке без
Telegram предлагается открыть приложение в боте; демо-входа и выбора actor нет.

JSON до 32КиБ, неизвестные/повторные поля отклоняются, даты с offset, версии через
If-Match, UUID повтора через Idempotency-Key. Origin проверяется при наличии,
CORS не включается. CSP разрешает собственные ресурсы и официальный Telegram SDK.
Персональные ответы no-store, исключения/сырой auth/тела не логируются.
Лимиты на процесс: вход 10/мин/IP (за текущим прокси общий loopback IP), чтение
120/мин/actor, изменение 20/мин/actor. Для масштабирования понадобятся общий limiter
и доверенный real-IP; в тесте лимит входа общий, это известное ограничение.

## Данные и действия

Клиент: существующий профиль или регистрация с действующим текстом бота, свободные
даты/слоты, создание заявки с предварительным просмотром, предстоящие/история,
запрос переноса и отмена с подтверждением. Email не объявляется подтверждённым.
Администратор: календарь, заявки/счётчики, отдельные входящие переносов,
согласование/отказ с причиной, прямой перенос/отмена и шесть настроек записи.
Выбор слотов и все мутации используют общий слой бота. Длительность переноса
берётся из встречи, решения исходной заявки не перезаписываются переносом/отменой.
Уведомления отправляет общий outbox; Google/SMTP в текущем тестовом окружении выключены.

GET DTO содержит разрешённые действия и только необходимые поля. Клиент не видит
чужие имена/email; availability никогда не содержит карточек. Списки ограничены,
cursor подписан и связан с actor/маршрутом/фильтрами. Пагинация использует offset:
при параллельных добавлениях между страницами возможны смещения, обновление раздела
начинает список заново. Календарь UI показывает до 100 записей месяца; полный список
с пагинацией доступен в «Заявки».

Уточнение контракта 09: mutation возвращает стабильный результат общей команды
(ID/version/status и соответствующие meeting_id/reschedule_request_id), а не DTO,
собранный из уже изменённого ресурса. UI после успеха заново запрашивает GET.
Так replay возвращает сохранённое значение даже после дальнейших изменений.
GET operations выдаёт этот же результат; неизвестная/чужая операция — 404.
`retry-sync` и генерация OpenAPI в этой первой связке ещё не включены;
Google-подключение остаётся в боте. Остальные основные маршруты документа 09
подключены. Юридическое расширение согласия этим техническим этапом не выполнялось.

## Проверки и возврат

HTTP-тесты используют подписанную синтетическую initData, fake Telegram/Google
и временную SQLite. Браузерный прогон — отдельный локальный synthetic QA server,
SDK подменён только в тестовом браузере. Тестовые токены/initData не включаются в логи.
Живой вход Telegram с телефона должен дополнительно проверить пользователь.

Выкладка: backup тестовой БД → upgrade 0012 → новый image → health/сохранность
записей → включение только тестовых маршрутов → nginx -t/reload → HTTPS smoke →
меню тестового бота «Открыть Meetly». До настройки меню старое значение сохраняется.
При проблеме убрать только новые location/флаги и вернуть прежний image.
Additive api_sessions совместима с прежним ботом, откат образа не требует
возврата старой БД: новые принятые заявки не теряются.

Повтор браузерного QA: в одном терминале
`python -m tests.miniapp_qa_server`, в другом `node miniapp/verify-live.mjs`.
Только synthetic QA database .deploy/miniapp-qa.db; fixture server слушает
127.0.0.1:18713 и не попадает в Docker runtime. При повторе начинать с нового
fixture server. Прогон сохраняет только синтетические снимки и PASS/FAIL.
